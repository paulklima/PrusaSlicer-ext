# Research report A — GUI / paint / storage integration (2.9.6)

All paths relative to the repo root. Verified against version_2.9.6 sources.

Main risks: (a) stock PrusaSlicer can crash on paint states ≥3 (R1); (b) a stroke that fully
covers a triangle wipes its manual sub-triangle paint (R2); (c) a facet holds only one state, so
P3 breaks where causes overlap (R3); (d) a background job must not read live PrintObject data (R5).

## 2. TriangleSelector (`src/libslic3r/TriangleSelector.{hpp,cpp}`)

- `TriangleStateType : uint8_t` (hpp:36-60): NONE=0, ENFORCER=1, BLOCKER=2, `Extruder3..16` = 3..16; `TRIANGLE_STATE_TYPE_COUNT=256` (62). States 3..15 storable in `supported_facets`.
- Encoding (cpp:1810-1833, 1876-1902): states 0–2: 4 bits/leaf; 3–16: 8 bits; 17–255: 16 bits. `minimum_required_painting_version()` (2061-2065) = 1 if all states ≤16 (readable by 2.4–2.9.4).
- `select_patch` (243-279): BFS over original facets; seeds from `cursor->get_facets_to_select()` (virtual, default = hit facet, hpp:119); `highlight_by_angle_deg` filter (268); expands only if `select_triangle` returns true.
- `select_triangle_recursive` (1066-1116): **fully inside → `undivide_triangle` + `set_state(type)` (1082-1085), discarding children with other states (erases manual sub-triangle paint)**. Partially inside: early return if leaf already has target state (1090-1093); else split or `set_state` (1096-1099); recurse. `remove_useless_children` (1320-1356) merges uniform children.
- Cursors: `Sphere`, `Circle`, `Capsule3D`, `Capsule2D`, `HeightRange` (hpp:191-267). `HeightRange` overrides `get_facets_to_select` (all facets crossing a z band, cpp:2434-2462), `m_edge_limit = 0.1` (2415); otherwise edge limit `radius/5` (2187). Cursor ctor protected; overrides need protected `Triangle`/`Vertex` types → **a new cursor must be a nested class in TriangleSelector.hpp**. "3 vertices inside" = fully inside only for convex cursors; a non-convex prism must override `vertices_inside` (virtual, hpp:115).
- Seed fill: `seed_fill_select_triangles` (304-368) by normal angle regardless of state; `bucket_fill_select_triangles` (576-639) same state; `seed_fill_apply_on_triangles` (2134-2150). `reset()` (1418-1436), `set_facet()` (1118-1123, undivides).
- **`remap_states(map)` (1125-1143)** replaces states on leaves and merges → ready for per-cause clearing.
- `get_facets(state)`, `get_facets_strict(state)` (1585, 1639) equality compare; template overloads with `std::function<bool(const Triangle&)>` exist (hpp:369/379) but are defined in the .cpp → a non-template overload taking a state set is cleaner. `has_facets(data, state)` (2068-2116).
- Protected-states mode is easy, local to `select_triangle_recursive`: skip protected leaves (return true to keep searching); in the fully-inside case recurse into children instead of undivide when the subtree has a protected leaf. More general: a `std::function<TriangleStateType(old, requested)>` paint rule applied at each leaf assignment (1085, 1099) → protection, cause bitmasks, suppression in one mechanism.

## 3. Rendering

- `TriangleSelectorGUI` (GLGizmoPainterBase.hpp:38-75, cpp:973-1075): one `GLModel` for enforcers, one for blockers, `std::array<GLModel,3> m_iva_seed_fills`; shader `gouraud`; colours enforcer {0.47,0.47,1}, blocker {1,0.44,0.44} (975-976).
- `update_render_data` (1039-1063): **any state other than NONE/ENFORCER goes into the blocker (red) buffer**; seed-filled triangle indexes `iva_seed_fills_data[tr_state]` (1044, 1047).
- **R1:** a state ≥3 triangle that is seed-selected (Smart fill hover or "Triangles" brush, cpp:752-758) indexes out of bounds of the size-3 array → UB/crash. Must be fixed in the fork; **stock PrusaSlicer opening our 3MF is affected**.
- `TriangleSelectorMmGui` (GLGizmoMmuSegmentation.hpp:69-86, cpp:659-715): one vertex VBO + one index buffer per colour (size `2*(colors+1)`, second half for seed fill), shader `mm_gouraud` with `uniform_color`; states above `colors.size()` fall back to 0 (698).
- Gizmo calls virtual `render(ImGuiWrapper*, const Transform3d&)` (hpp:44); protected: `m_update_render_data`, `get_seed_fill_color`, `update_paint_contour`, `render_paint_contour`, `m_triangles`, `m_vertices` → a `TriangleSelectorFdmGui` subclass can own per-state GLModels with a palette, like the MMU one. Create it at GLGizmoFdmSupports.cpp:492. `render_triangles` sets `gouraud` uniforms (GLGizmoPainterBase.cpp:78-122). Seam/fuzzy-skin gizmos keep the base class (GLGizmoSeam.cpp:234, GLGizmoFuzzySkin.cpp:294).

## 6. Pipeline step, threading, jobs

- `posSupportSpotsSearch` (Print.hpp:89-91); `generate_support_spots()` (PrintObject.cpp:494-516) stores `{trafo, points, partial_objects}` in `m_shared_regions->generated_support_points`. **Not gated:** `Print::process()` runs it for every object on every slice (Print.cpp:920-925). Invalidated by perimeter/infill/slice changes (PrintObject.cpp:968-977); reset in `Print::cleanup` (PrintApply.cpp:1760-1761).
- `reslice_FFF_until_step` (Plater.cpp:6564-6593) sets `task.to_object_step` + single-instance mode **only if background processing is disabled**; otherwise the full pipeline runs with the object first. `set_task_impl` (PrintBase.hpp:629-715).
- `lslices`, `lslices_ex[].{bbox, overlaps_*}` written only during posSlice (Layer.cpp:80-83, 513-531; PrintObjectSlice.cpp:556-577); posPerimeters mutates `lslices_ex[].islands` (Layer.cpp:1011-1013). Reading `lslices` on the GUI thread after `is_step_done(posSlice)` is safe even while the background thread continues.
- **R5:** `Print::apply` runs on the GUI thread on every edit (Plater.cpp:2487) even while the UI worker is busy; it can delete PrintObjects (PrintApply.cpp:1581); a restarted `slice()` calls `clear_layers()` (PrintObjectSlice.cpp:537). **A worker thread must never read live PrintObject data; copy it on the GUI thread.**
- UI jobs (`src/slic3r/GUI/Jobs/`): `Job::process(Ctl&)` on worker, `finalize(canceled, eptr)` on UI thread; `Ctl` has `update_status`, `was_canceled`, `call_on_main_thread` (Job.hpp:19-57); `queue_job`/`replace_job` (Worker.hpp:63-103). `Plater::get_ui_job_worker()` (Plater.cpp:5495) = `PlaterWorker<BoostThreadWorker>` with `NotificationProgressIndicator` → progress notification with cancel button (BoostThreadWorker.cpp:97). Exceptions shown by `PlaterJob::finalize` (PlaterWorker.hpp:86-91). While the UI worker is busy `restart_background_process` refuses (Plater.cpp:2663-2667), slicing progress suppressed (3299-3302). Patterns: `RotoptimizeJob` (prepare() in ctor on UI thread, RotoptimizeJob.cpp:23, 54, 93), gizmo usage GLGizmoRotate.cpp:689-694. Alternative with in-panel progress: `GLGizmoSimplify` own `std::thread` + `ImGui::ProgressBar` (GLGizmoSimplify.cpp:361-367, 384-404, 467-512).
- Recommendation: UI worker with a copied snapshot. Not a new PrintObjectStep (it would be invalidated by its own paint output, since the plan depends on manual paint).

## Recommended integration (researcher's proposal)

Computation: button → same pre-checks as 523-544 + P7 contract check → own `m_smart_waiting` flag → `CallAfter(reslice_FFF_until_step(posSlice, mo))` → wait for `po->is_step_done(posSlice)` in `data_changed` (with background processing on, also poll via `m_parent.schedule_extra_frame`, GLCanvas3D.hpp:930) → on the UI thread copy per layer `lslices` (+overlaps), `slice_z`, `print_z`, `height`; `trafo_centered`, instance trafo, config values; per volume `mesh_ptr()` (Model.hpp:808), `supported_facets` data + timestamps → `replace_job(get_ui_job_worker(), SmartSupportsJob)`; `process()` computes the joint plan, paints private TriangleSelector copies, verifies via `slice_mesh_slabs` → `finalize` on UI thread: discard if gizmo closed / ids changed / timestamps changed; else one `TakeSnapshot(GizmoAction)`, deserialize into `m_triangle_selectors`, `request_update_render_data()`, `update_model_object()` (invalidates only posSupportMaterial).

Storage in `supported_facets` states: recommended with fixes.
- Pros: undo/redo, 3MF, copy/split, mesh-edit reset, "Remove all", info item, Print::apply invalidation unchanged; manual and auto paint mutually exclusive in one tree; per-cause clear = `remap_states`; existing button already clears.
- R1: fix our GUI. Stock compatibility: **bake on 3MF export** — write `slic3rpe:custom_supports` with auto states remapped to ENFORCER, plus a fork-only per-triangle attribute with the true states; on load the fork prefers the fork attribute. Stock then slices like the fork, shows blue paint, never meets states ≥3; if stock re-saves, auto paint degrades to manual enforcers.
- R3 (P3): bitmask states `3 + (mask-1)` for mask 1..7 → states 3–9; suppression 10–16; all within version 1. Paint rule `NONE → cause`, `auto(m) → auto(m|c)`, ENFORCER/BLOCKER untouched; clear `remap m → m&~c`.
- P6 suppression: Shift-erase maps auto states to a suppressed state via the same hook; also in `seed_fill_apply_on_*` (2134-2159).
- Fingerprint: gizmo memory + an extra 3MF archive file.

Painting: paint-rule hook in `select_triangle_recursive`; nested `PrismCursor` in TriangleSelector (seeds from `get_facets_to_select` like HeightRange; `vertices_inside` < 3 when polygon edges cross the triangle (non-convex, R4); `is_facet_visible` true; `highlight_by_angle_deg = 89.99`; bounded edge limit — dense subdivision inflates 3MF and undo stack, R7).

Rendering: `TriangleSelectorFdmGui` subclass, one GLModel per cause colour, "show causes" toggle, seed-fill colours per state. Clear per cause: `remap_states` → TakeSnapshot → `update_model_object()`.

Files: `TriangleSelector.{hpp,cpp}`; `Model.{hpp,cpp}`; `PrintObject.cpp:3429-3457`; `Print.cpp:711`; `Format/3mf.cpp` (bake on write + fork attribute); `GLGizmoFdmSupports.{hpp,cpp}`; `GLGizmoPainterBase.cpp:1043-1049` (OOB fix); new `src/libslic3r/SmartSupports/*`; `src/slic3r/GUI/Jobs/SmartSupportsJob.{hpp,cpp}`; CMakeLists entries.

Conflict: theory P6 says auto paint is stored "separately from the TriangleSelector states" — using states 3+ puts the source tag into the states; amend that wording.
